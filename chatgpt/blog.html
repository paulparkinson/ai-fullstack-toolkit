Quick reference: Server URL or Tunnel?

These are the values entered in ChatGPT’s Add custom MCP server dialog. Example hosts and tunnel IDs below are placeholders, not deployed endpoints.

The loopback URL is configured in the tunnel client, not entered as a remote Server URL in ChatGPT. A stdio command cannot be pasted into that field. The Python and SQLcl rows require the adapter changes described below. A remotely hosted app adapter could instead provide its own HTTPS Server URL.

What must stay running for this plugin to work?

This local-process explanation applies to the Java Toolkit demonstration. A directly connected, remotely hosted ORDS server uses the separate deployment described below.

Both Java and Node.js must run, plus the OpenAI tunnel client. The plugin uses this chain:

ChatGPT plugin
    ↓ private tunnel
Node.js MCP App server
    ↓ starts and manages
Oracle Database MCP Java Toolkit
    ↓
Oracle database
  • Node.js serves the plugin’s tools and embedded dashboard.
  • Java Toolkit connects to Oracle and executes the SQL. The Node server starts it automatically as a child process.
  • Tunnel client lets ChatGPT reach your local Node server.

From the repository root, keep these running in two PowerShell windows:

# Window 1: starts Node and its Java Toolkit child
.\chatgpt\run.ps1 -Profile OCI
# Window 2: connects ChatGPT to the Node server
.\chatgpt\connect-tunnel.ps1 -TunnelId YOUR_TUNNEL_ID

npm is the package/build tool, not another service you need to keep running. You also don’t need a separately launched Java HTTPS server with this configuration.

If this computer sleeps or either window closes, the installed plugin remains in ChatGPT, but its database calls stop working. The downloaded demo video works independently.

Add the MCP App as a ChatGPT plugin

The installation walkthrough below shows the actual ChatGPT interface. The settings form was reopened for this explanation and uses tunnel_... instead of a private identifier. The installed plugin and working dashboard are real. No duplicate plugin was created for these screenshots.

  1. Start the app and private tunnel. Build the app using the Windows commands below. Leave .\chatgpt\run.ps1 -Profile OCI running in one PowerShell window. In a second window, from the repository root, run .\chatgpt\connect-tunnel.ps1 -TunnelId tunnel_..., replacing the placeholder with your tunnel ID. A runtime key is an OpenAI API key used by the tunnel client; it is separate from your Oracle password. Supply it at the hidden prompt or through the ignored .env variable CHATGPT_KEY_FOR_MCPAPP_PLUGIN. Runtime permissions need Tunnels Read and Use. Keep both processes running and verify that http://127.0.0.1:8766/readyz returns ready.
  2. Open ChatGPT Plugins. Choose Add → Add custom MCP server.
  3. Configure the connection. Enter FinancialDB Notes as the name and a short description. Select Tunnel and enter the same tunnel ID used by your running client. Select No authentication for this private demo, whose transport uses the authorized tunnel. This option does not add app-level OAuth.
  4. Create and connect. Read the access warning, check I understand and want to continue, and select Create as a plugin. ChatGPT initializes the MCP server and discovers its tools. Complete the Connect FinancialDB Notes prompt when shown. If setup fails, confirm tunnel readiness and run both smoke checks below before retrying.
  5. Try it in a conversation. The installed plugin page offers Try in chat. Select it, or select FinancialDB Notes with @ in a new conversation, and send Show my FinancialDB notes. Open its dashboard. Read only; do not add any notes.
  6. Verify the live result. The dashboard should say Loaded from Oracle FinancialDB. Select Refresh notes to test the interactive bridge. The saved demonstration below shows the approved conference note returned from Oracle.

To review this article on another machine, pull this repository and open chatgpt/blog.html. The screenshots, narrated MP4s, poster, and captions are included in Git. You can play chatgpt/video/oracle-chatgpt-walkthrough.mp4 directly without database credentials. For browser caption tracks, serve the article over HTTP, for example python -m http.server 8000 --directory chatgpt, then open http://localhost:8000/blog.html.

Follow the request from the app to Oracle

ChatGPT or the local MCP App test host
  → Streamable HTTP /mcp on loopback
  → server.ts: named tools and bundled UI resource
  → Oracle Database MCP Java Toolkit over stdio
  → toolkit-tools.yaml: parameterized SQL
  → Oracle CHATGPT_NOTES table

This sample lives in the AI Fullstack Toolkit repository and delegates database execution to its vendored Oracle Database MCP Java Toolkit. It does not route these notes through the Java framework's approval gate or its simulator backends.

show-financialdb-notes is the model-visible, read-only entry point. It returns the latest 50 notes and references ui://financialdb/chatgpt-notes-v1. The app-only refresh and insert tools use the official MCP App bridge. The ChatGPT server uses the MCP v2 dual-era HTTP handler to support both protocol 2026-07-28 and legacy initialization. The Oracle Toolkit connection retains its legacy handshake. A person must check the confirmation box before the UI sends an insert.

The checkbox is a UI confirmation, not server-side authorization. App-only visibility guides compatible hosts; it is not an access-control boundary for an arbitrary MCP client. This private demo must remain behind the authorized tunnel. A production service needs authenticated callers and a server-enforced approval policy appropriate to its writes.

Use the repository environment file

The new cross-platform configuration reader loads the root .env, then optional chatgpt/.env, then process-environment overrides. It defaults to the OCI profile; set CHATGPT_DB_PROFILE=GCP to select GCP. Explicit DB_URL, DB_USERNAME, and DB_PASSWORD override the selected profile. Values are parsed literally without executing shell commands.

Only the Oracle child process receives the selected database credentials. The tunnel runtime key is excluded from database configuration loading and from that child's environment. A valid local wallet path is used when present. The configured JDBC descriptor is preserved when no local wallet exists; whether that works depends on the database's TLS configuration.

Connect the private plugin to ChatGPT

  1. In OpenAI Platform tunnel settings, select a tunnel associated with the intended ChatGPT workspace. Reuse a suitable existing tunnel. Tunnel management needs Read and Manage permissions; runtime use needs Read and Use.
  2. Install the official tunnel-client. With the local app running, execute .\chatgpt\connect-tunnel.ps1 -TunnelId tunnel_... from the repository root. Enter an existing runtime key at its hidden local prompt, or use the explicitly configured CHATGPT_KEY_FOR_MCPAPP_PLUGIN in the ignored root .env. The launcher reads that variable only for the tunnel process. Keep the process running. The script verifies configuration before starting the tunnel. Do not paste the key into chat or a recording.
  3. Check http://127.0.0.1:8766/readyz. In ChatGPT Plugins, choose Add → Add custom MCP server. Name it FinancialDB Notes, choose Tunnel, and select or enter the same tunnel ID. This sample provides no app-level OAuth; use No authentication only with the authorized private tunnel.
  4. Review the access warning and discovered tools, then create and install the private plugin. In a new conversation, select it with @ and ask Show my FinancialDB notes. Successful rendering and a live notes read in ChatGPT complete the host verification.
  5. For an approved demonstration write, enter a clearly identified demo note, check the confirmation box, select Add note, and refresh to verify persistence.

Follow the current OpenAI Secure MCP Tunnel guide and custom MCP server instructions for account-specific access. Tunnel transport supports private use; public plugin distribution requires a different deployment path.

Use another Oracle AI Database MCP server

The database MCP server and the MCP App are separate components. This implementation uses the Java Toolkit for its configured SQL operations; Node supplies the FinancialDB tools and dashboard resource. Another database MCP server can replace the upstream component after adapting its transport, tool arguments, and results. These alternatives are integration guidance; the video demonstrates the Java Toolkit implementation.

Oracle DB Tools MCP server: OCI connections and Python

Oracle’s DB Tools MCP server is a Python/FastMCP proof of concept, explicitly described as unsuitable for production. It discovers OCI resources and Database Tools connections and offers SQL, table, and report tools over stdio. It uses OCI SDK credentials in ~/.oci/config; PROFILE_NAME selects a profile. This sample’s JDBC variables do not configure it. See the installation and tool reference.

In a separate checkout of oracle/mcp, install dependencies and launch:

cd src/dbtools-mcp-server
python -m pip install -r requirements.txt
python dbtools-mcp-server.py

Its SQL tool accepts a Database Tools connection display name and SQL script. Report tools support report definitions and bind values. Configure the intended OCI connection and permissions before testing. For this ChatGPT app, Node would launch and manage the Python stdio child instead of Java; a separately started stdio process is not an HTTP endpoint for the tunnel.

Oracle SQLcl MCP server: reuse saved database connections

Oracle SQLcl’s MCP server exposes database tools using preconfigured named or saved SQLcl connections. It supports SQL, PL/SQL, and SQLcl commands. Oracle documents configuring an MCP client to launch SQLcl with -mcp and manage its lifecycle. Use your installation’s executable path and follow the SQLcl launch configuration:

# Invocation for a local MCP client or backend stdio adapter:
sql -mcp

This path replaces the Toolkit child with SQLcl and its Java runtime. Node and the tunnel still serve this dashboard’s ChatGPT-facing connection.

Oracle ORDS MCP server: direct remote access without a local install

Oracle documents MCP in ORDS 26.2 standalone. An administrator must enable feature.mcp, configure JWT authentication, and authorize database pools. The endpoint is https://<ords-host>/mcp, not /ords/<schema>/mcp. The documented MCP runtime is unavailable in Tomcat or WebLogic deployments. See Oracle’s ORDS MCP configuration guide.

ORDS requires bearer JWT authentication and publishes protected-resource metadata at /.well-known/oauth-protected-resource/mcp. Its identity provider and database scopes or roles must be configured for the intended callers. See ORDS authentication and protocol details.

In ChatGPT, select Server URL, enter the remotely reachable HTTPS endpoint, and configure OAuth for that deployment. ChatGPT supports remote streaming HTTP and OAuth; see OpenAI’s custom MCP server instructions. Thus, with compatible OAuth configuration and workspace access, this direct remote route needs no Java, Node.js, npm, Python, SQLcl, or tunnel client installed on the user’s ChatGPT computer. The ORDS service and identity provider run on server infrastructure reachable by ChatGPT. An intranet-only hostname is not sufficient for direct access.

Direct ORDS access exposes its database tools; it does not automatically provide this FinancialDB Notes dashboard. Retaining that UI requires adapting and hosting the Node MCP App layer, then connecting ChatGPT to that app endpoint. ORDS is documented here as an alternative; no ORDS deployment or end-to-end ChatGPT OAuth connection was tested in this repository.

Adapt the backend while keeping the dashboard

The following is an integration plan based on this repository’s code; these alternatives are not already wired up:

  1. Change the upstream transport in server.ts. Its stdio branch hardcodes the Toolkit Java command. Replace it with a Python or SQLcl child and pass only that backend’s configuration. The current run.ps1 continues to launch the Java Toolkit until changed.
  2. Discover and map upstream tools. The adapter currently calls list-chatgpt-notes and add-chatgpt-note, names defined by toolkit-tools.yaml. Other servers have different schemas. Preserve the public notes tools, implement their fixed operations with the selected backend, and normalize reads to structuredContent.rows containing note_id, note_text, and created_at.
  3. Preserve write handling. Use backend-supported binds or a fixed stored procedure/report for note text. Do not concatenate user input into SQL. Keep UI confirmation and enforce authorization on the server where required.
  4. Keep the MCP App resource. A database tool server alone does not supply this dashboard. Retain Node’s tool metadata, bundled UI resource, and App bridge. Changing only ORACLE_MCP_URL is insufficient when tool contracts differ; that variable configures the existing HTTP upstream branch, not a stdio command.
  5. Verify the adapted path. Test discovery, result normalization, resource rendering, and live refresh before an explicitly approved demo write. Keep Oracle/OCI credentials in backend processes. The tunnel continues to target Node’s app endpoint.
